# StudyAgent: RLHF & PPO Implementation Plan

This document outlines the comprehensive strategy to transform the StudyAgent codebase into a Reinforcement Learning (RL) environment and train an open-source tutor model using SFT, SRL, and RLHF (PPO).

## 1. Architecture: The Hierarchical SRL System

To ensure the system makes correct pedagogical decisions at both the *strategic* (Plan) and *tactical* (Response) levels, we will implement **Hierarchical Supervised Reinforcement Learning**.

We will train **two separate agents**:

### Agent A: The Planner (Level 2)
*   **Role**: Strategic decision maker.
*   **Task**: Given a Student Profile + Concept, generate the optimal `SessionPlan` (sequence of steps).
*   **SRL Approach**:
    *   **Reasoning**: The model generates the plan step-by-step.
    *   **Expert Trajectory**: High-quality plans generated by SOTA (GPT-4o) that lead to high mastery.
    *   **State**: Student Profile, Concept Graph.
    *   **Action**: Next `PlanStep` (Pedagogy + Content).

### Agent B: The Tutor (Level 3)
*   **Role**: Tactical executor.
*   **Task**: Given the current `PlanStep` + Student History, generate the text response.
*   **SRL Approach**:
    *   **Internal Monologue**: The model must output a thought trace and specific tactic *before* speaking.
    *   **Action Space**: `[Thought] -> [Micro-Strategy] -> [Text Response]`.
        *   *Example*: `[Thought: Student is stuck on the math.] [Strategy: Provide Worked Example] "Let's look at the numbers..."`
    *   This ensures the model explicitly **learns to pick the correct pedagogical action**, not just the words.

## 2. RL Definitions

### Agent A: The Planner (L2)
*   **State**: Student Mastery Map ($M$), Target Concept ($C$).
*   **Action**: Sequence of Steps $S_1, S_2, ... S_N$.
*   **Reward**:
    *   $r_{validity}$: Is the plan logically consistent? (DAG check).
    *   $r_{coverage}$: Does it cover the concept's key chunks?
    *   $r_{predicted\_mastery}$: (From a Simulator) How much would a student learn from this plan?

### Agent B: The Tutor (L3)
*   **State ($s_t$)**:
    *   **Context**: Concept, Current `PlanStep`, RAG Chunks.
    *   **History**: Conversation History.
    *   **Mastery**: Current Delta ($\Delta_m$).
*   **Action ($a_t$)**:
    *   **Component 1 (Hidden)**: `[Reasoning] [Strategy]` (e.g., *Ask Socratic*, *Give Hint*, *Correction*).
    *   **Component 2 (Visible)**: The final text output.
*   **Reward ($r_t$)**:
    *   $r_{mastery}$: Actual mastery gain detected in DB ($\Delta_{mastery}$).
    *   $r_{alignment}$: Did the text match the chosen `[Strategy]`? (Critic Check).
    *   $r_{quality}$: Pedagogy Score (Critic).

## 3. Development Phases

### Phase 1: Instrumentation & Environment (Local)
**Goal**: Enable the codebase to generate training logs and compute rewards.

1.  **Unified Logging Schema (`tutor_turn`)**:
    *   Ensure every turn logs: `mastery_before`, `mastery_after`, `mastery_delta`, `plan_step`, `rag_context_ids`.
    *   Format: JSONL lines for easy training ingestion.
2.  **LLM Client Abstraction**:
    *   Update `backend/mdp/llm_client.py` to support switching between:
        *   **Teacher Mode**: Calls SOTA (GPT-4o/Claude-3.5) for data generation.
        *   **Student Mode**: Calls a weaker/different model for simulation.
        *   **Policy Mode**: Calls local/remote endpoint of the model being trained.
3.  **Mastery Signal Refinement**:
    *   Ensure `InputAnalyzer` outputs granular correctness scores (0.0–1.0).
    *   Ensure `MasteryModel` commits updates immediately after turns so `delta` is accurate.

### Phase 2: Data Generation Pipeline (Robust & Adversarial)
**Goal**: Create high-quality datasets covering diverse, difficult scenarios.

1.  **Adversarial Student Simulator**:
    *   Don't just use a "perfect" student. Create personas:
        *   *The Rusher*: Wants to skip steps.
        *   *The Confused*: Keeps making the same mistake.
        *   *The Challenger*: Asks off-topic questions.
    *   This forces the Teacher Model to demonstrate **corrective** and **adaptive** pedagogy.

2.  **Dataset 1: Planner Trajectories (SRL)**:
    *   Input: `StudentProfile(Novice)` + `Concept(Thermodynamics)`.
    *   Output: `[PlanStep(Explain), PlanStep(Analogy), PlanStep(Quiz)]`.
    *   Source: Teacher Model (SOTA).

3.  **Dataset 2: Tutor Trajectories (SRL)**:
    *   **Teacher Prompting**: Force the Teacher Model to output `[Strategy]` tags.
    *   *Example Data*:
        *   Input: "I don't get it."
        *   Output: `[Thought: User missed the core definition] [Strategy: Simplify & Analogy] "Think of heat like water flowing..."`

4.  **Dataset 3: Preference Pairs**:
    *   Same as before, but Critic evaluates both the `[Strategy]` choice and the Text.

### Phase 3: Training Infrastructure (Cloud GPU)
**Constraint**: No local GPU.
**Solution**: Use Cloud GPU Rentals (RunPod, Lambda Labs, or Vast.ai) + TRL Library.

1.  **Step 3.1: Train Planner (L2)**:
    *   Fine-tune a small model (e.g., Llama-3-8B or even smaller) to generate JSON plans.
    *   Objective: Minimize distance to Expert Plans.

2.  **Step 3.2: Train Tutor (L3) with SRL**:
    *   **SFT Stage**: Train on Dataset 2 (Trajectories with Thought Traces).
        *   This "clones" the expert's decision-making process.
    *   **RL Stage (PPO)**:
        *   Reward Model evaluates the *Text*.
        *   Environment provides *Mastery Delta*.
        *   The model learns to pick the `[Strategy]` that maximizes these rewards.

### Phase 4: Evaluation
1.  **Pedagogical Accuracy**:
    *   "Did the model choose 'Socratic Question' when the student was 80% correct but unsure?" (Classifier Eval).
2.  **Real-World Robustness**:
    *   Run against the **Adversarial Student Simulators**.
    *   Metric: How many turns to correct a stubborn misconception?
3.  **Mastery Gain**:
    *   Average $\Delta_{mastery}$ per session.
